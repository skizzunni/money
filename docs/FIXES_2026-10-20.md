## 2. The 0-trade run (`5feac8dc-...04-54_AM.csv`, 8/9 to 10/17, 0 trades, $0 commission)

**The PDF's first-ranked cause, warm-up never completed, does not hold on these bars.**
- The run's code is most likely commit 5c7626a (docs/NATIVE_RUNS.md section 5). That version was built and run on
  the user's MNQ bars from 8/9 (09-26 to the roll, 12-26 after; simulator, $0.95 a side).
- With its defaults it took **83 trades**. The engine was ready, and the first entry came on 8/28.
- So 14 full sessions fit inside 8/9 to 10/17.

**Two of the PDF's causes cannot have applied to that version:**
- `EvaluationStart` belongs to candidate C, which did not exist yet.
- "Not enabled" does not apply in the Strategy Analyzer.

**What can produce exactly 0 trades and $0 commission there:**
- **Place orders Off.** Reproduced: 0 trades, while the Output fills with "Place it now (orders are off)" lines.
- **A non-minute series, or Calculate not "On bar close".** The strategy prints "... Not trading." and does nothing.

**Which one it was needs that run's NinjaScript Output.** It was not saved, so the run stays unresolved. The checks
below make a repeat impossible to miss:
- **B:** before the first session, the "MNQ settings:" lines must show the account, orders ON and the settings. The
  daily line must read "ready, trading today" from the 15th full session.
- **C:**
  - 1-minute chart, trading hours CME US Index Futures ETH, Days to load 45;
  - MnqMomentumC Enabled on the simulation account;
  - EvaluationStart empty (or the evaluation's real first session, never a future date);
  - Place orders On;
  - the "C settings:" line printed before 09:30 New York;
  - after a run, "C audit: engine ready (14 full sessions) from ..." (it reads "never" if warm-up failed).

## 4. Code: realtime errors are no longer ignored

**The change:**
- `RealtimeErrorHandling` is now `StopCancelCloseIgnoreRejects` in all three strategies: MnqNoiseMomentum (B),
  MnqMomentumC and MnqMomentumRunner. Before, it was `IgnoreAllErrors`.
- **Why "IgnoreRejects" and not plain StopCancelClose:**
  - Each strategy handles a rejected order itself in OnOrderUpdate:
    - B re-sends a rejected exit of its own at the next bar, and closes the position at market on any other rejected
      order while in a position;
    - C and the runner close the position at market, and try again at each bar until flat.
  - Plain StopCancelClose would stop the strategy before that handling runs.
  - Every other realtime error now stops the strategy, cancels its orders and closes the position.
- **Test:** `tests/test_ninjatrader.py::test_realtime_errors_are_never_ignored`, for all three.
- **Backtests:** the setting acts only in realtime. On the simulator, B's 97 MNQ trades, C's 28 and the runner's 26 are
  identical before and after.

**B is now v1.1** (`release/MnqMomentumB_v1.1`):
- MnqNoiseMomentum.cs sha256 `d1a4f8633c0d630edabd02ed59b8be0425eda581ab322873db58ecc8cbd26a35`.
- **It is frozen B's trading logic unchanged; only the error handling differs.** The engine file is v1's.
- v1 (`1fbdcea0...`) stays in `release/MnqMomentumB_v1` as the code reconciled with native NinjaTrader. It is marked
  superseded for any account.
- The Pine reference package now carries v1.1's file too, so only one MnqNoiseMomentum.cs version is in circulation.
